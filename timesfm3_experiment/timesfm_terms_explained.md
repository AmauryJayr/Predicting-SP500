# h、zero-shot、ROC-AUC、balanced accuracy 是什麼

這四個詞在 TimesFM 報告（`experiments/TIMESFM_REPORT.md`）裡都會出現。前三個依難度排列：h 最簡單，zero-shot 次之，ROC-AUC 最難，所以篇幅最長。第 4 節補充 balanced accuracy（BA），它是報告裡另一個主要分數。

---

## 1. h：預測的距離（horizon）

h 是 horizon 的縮寫，意思是「往未來看幾個交易日」。專題裡有兩種：

- **h=1**：標籤是 `Close[t+1] > Open[t+1]`，問的是明天收盤會不會高於明天開盤。
- **h=5**：標籤是 `Close[t+5] > Open[t+1]`，問的是 5 個交易日後的收盤，會不會高於明天開盤。

t 是做決定的那天。我們在第 t 天收盤後，用當天為止的資料去猜。

用一組數字算一次：

| 日子 | 開盤 | 收盤 |
|---|---|---|
| t（今天） | | 100 |
| t+1 | 101 | 102 |
| t+5 | | 100.5 |

- h=1：比較 Close[t+1] = 102 和 Open[t+1] = 101。102 > 101，所以標籤 y = 1（漲）。
- h=5：比較 Close[t+5] = 100.5 和 Open[t+1] = 101。100.5 < 101，所以標籤 y = 0（跌）。

同一個 t，兩個 h 的答案可以相反，所以兩個 horizon 要分開評估，各自選設定、各自報結果。

為什麼兩個標籤都是和 Open[t+1] 比？因為第 t 天收盤後才做決定，最早只能在第 t+1 天開盤時進場。用 Open[t+1] 當起點，才是實際上做得到的報酬。這是專題的設計選擇。

---

## 2. Zero-shot：沒有用這個任務的資料訓練

先講清楚「訓練」是什麼：訓練就是用有標籤的資料去調整模型的參數（parameters，模型內部的數字）。

拿專題裡的兩個模型對照：

**組內的 LR（邏輯迴歸）**

- 有 23 個權重加 1 個截距，一共 24 個數字。
- 一開始這些數字不知道是多少。我們拿 2008–2018 年每天的 23 個特徵和漲跌標籤去調整它們，直到預測和標籤最吻合。
- 用的是 SPY 漲跌的資料，這就是在「這個任務上」訓練。

**TimesFM-3**

- 有 330,710,976 個參數。Google 已經用網頁瀏覽量、搜尋熱度、合成曲線等資料把它們調好了。
- 我們下載這些數字之後，一個都沒有改。
- 每天只做一件事：把過去 256 天的價格當成輸入（context）交給它，讓它算出未來 5 天的分位數。

### 「看 context」不等於訓練

拿 2019-03-01 和 2019-03-04 這兩天來看：

- 2019-03-01 輸入的是 256 個價格（大約 2018-02 到 2019-03-01），2019-03-04 輸入的是往後挪三天的另一段 256 個價格。
- 兩天用的是同一組 330,710,976 個參數。
- 輸出不同，是因為輸入不同，不是因為模型學到了新東西。
- 算完 2019-03-01 之後，參數完全沒變。我們做過的批次測試也可以驗證：同一天的預測，不管單獨算還是和其他日子放在同一批算，結果都一模一樣。

### 「shot」這個詞的來源

shot 指的是這個任務的標籤範例有幾個。zero-shot 是 0 個，few-shot 是給幾個範例。這只是領域裡的命名習慣，字面上沒有更深的意思。

### 我們的做法嚴格來說不是 100% 零接觸

有兩處用到了 2013–2018 的標籤：

1. 從 10 組設定裡挑出最好的一組（`multi`，context 256）。
2. 校準用的 1 個數字 b（截距偏移）。

模型本身的參數一個都沒動，所以說 TimesFM「zero-shot」是對的。但報告裡最好老實寫：最後的預測流程有 1 個參數和 1 個設定選擇是用標籤決定的。

## 3. ROC-AUC：分數排得對不對

這是最需要細講的一個。它建立在 TP / FN / FP / TN 上。

### 3.1 模型輸出的是分數，不是答案

TimesFM 每天給的是一個 P(漲)，例如 0.6，而不是直接說「漲」或「跌」。要變成答案，得先選一個門檻（threshold）：分數 ≥ 門檻就判為漲。

**門檻一換，TP、FP 這些數字就跟著變。** ROC-AUC 的做法是把所有門檻都試過一遍，所以不需要先選門檻。

### 3.2 兩個比率

- **TPR**（True Positive Rate）= TP / (TP + FN)：真的漲的日子裡，有幾成被判為漲。這就是 Recall。
- **FPR**（False Positive Rate）= FP / (FP + TN)：真的跌的日子裡，有幾成被誤判為漲。

### 3.3 用 4 天實際算一次

| 日子 | 真實標籤 y | 模型分數 |
|---|---|---|
| A | 1（漲） | 0.8 |
| B | 1（漲） | 0.4 |
| C | 0（跌） | 0.6 |
| D | 0（跌） | 0.2 |

漲的有 2 天（A、B），跌的有 2 天（C、D）。把分數從高到低排：A 0.8、C 0.6、B 0.4、D 0.2。然後讓門檻從高往低移：

| 門檻（分數 ≥ 這個判為漲） | 判為漲的日子 | TP | FP | TPR = TP/2 | FPR = FP/2 |
|---|---|---|---|---|---|
| 0.9 | 沒有 | 0 | 0 | 0 | 0 |
| 0.8 | A | 1 | 0 | 0.5 | 0 |
| 0.6 | A、C | 1 | 1 | 0.5 | 0.5 |
| 0.4 | A、C、B | 2 | 1 | 1 | 0.5 |
| 0.2 | 全部 | 2 | 2 | 1 | 1 |

把每一列的 (FPR, TPR) 當座標點畫出來，依序連線，就是 **ROC 曲線**（Receiver Operating Characteristic；這個名字來自早期的雷達訊號研究，沿用至今而已）：

```
(0, 0) → (0, 0.5) → (0.5, 0.5) → (0.5, 1) → (1, 1)
```

```
TPR
 1.0 ┤         ●━━━━━━━━━●
     │         ┃
 0.5 ●━━━━━━━━━●
     ┃
 0.0 ●─────────┬─────────┤ FPR
     0        0.5       1.0
```

**AUC**（Area Under the Curve）就是這條線底下的面積：

- FPR 從 0 到 0.5，曲線高度是 0.5，面積 0.5 × 0.5 = 0.25。
- FPR 從 0.5 到 1，曲線高度是 1，面積 0.5 × 1 = 0.5。
- 加起來 AUC = **0.75**。

### 3.4 AUC 的另一種算法（比較直觀）

AUC 恰好等於：**隨機挑一個漲的日子和一個跌的日子，模型給漲的那天分數比較高的機率。**

用同樣 4 天驗證。一漲一跌的組合共有 2 × 2 = 4 組：

| 組合 | 分數比較 | 排對了嗎 |
|---|---|---|
| (A, C) | 0.8 > 0.6 | ✓ |
| (A, D) | 0.8 > 0.2 | ✓ |
| (B, C) | 0.4 < 0.6 | ✗ |
| (B, D) | 0.4 > 0.2 | ✓ |

4 組排對 3 組，3/4 = **0.75**，和面積算出來的一樣。兩種算法在數學上是等價的。

### 3.5 幾個關鍵數字代表什麼

- **AUC = 1**：每一組都排對，所有漲的日子分數都比跌的日子高。
- **AUC = 0.5**：只排對一半，等於沒有資訊。如果所有日子分數都一樣，每一組都是平手。平手算 0.5 組，所以 AUC 剛好是 0.5。專題的 chance 基準就是給每天同一個分數，所以 AUC 恰好是 0.5。
- **AUC < 0.5**：排反的比排對的多。把上面例子的分數全部改成 1 − 分數（A 0.2、B 0.6、C 0.4、D 0.8），4 組只剩 (B, C) 排對，AUC 變成 1/4 = 0.25 = 1 − 0.75。

所以 TimesFM 在 h=5 的 AUC 是 0.459，意思是：在 2019–2025 所有「一個漲日配一個跌日」的組合裡，TimesFM 只有 45.9% 給漲日比較高的 P(漲)，比一半還少。

### 3.6 為什麼專題用 AUC 選設定，而不是準確率

**原因 1：準確率會被「一律猜漲」騙過。** h=5 的 TEST 期間有 61.4% 的日子是漲。如果每天都猜漲：

- 準確率 = 0.614，看起來不錯。
- 但每天的分數都一樣，AUC = 0.5。

在結果表（`experiments/results/timesfm_test_levels.csv`）裡，chance 這一列正是這樣：accuracy 0.614，AUC 0.500。AUC 不會被這種沒資訊的模型騙過。

**原因 2：AUC 只看排序，不看分數的大小。** 把例子裡每個分數都加 0.1（A 0.9、B 0.5、C 0.7、D 0.3），4 組的大小關係完全沒變，AUC 還是 0.75。

這就是報告裡兩個做法成立的原因：

- 選設定時可以直接用 TimesFM 的原始 P(漲)，不用先校準。
- 校準只加一個常數 b、斜率固定為 1，不會改變排序，所以 AUC 不變。在 VAL 試跑時，校準前後的 AUC 都是 0.5052 和 0.5334，完全相同。

反過來，原本 Platt 校準在 h=1 學到的斜率是負的（−0.048），等於把分數的順序整個反過來。那樣 TEST 的 AUC 就會變成 1 − 原本的 AUC，測到的已經不是 TimesFM 本身的判斷。這就是當初改用只調截距的原因。

## 4. Balanced accuracy（BA）：兩類日子各算一次命中率

報告裡的原文：

> Balanced accuracy (BA) is the average of two hit rates: the share of up-days called "up" and the share of down-days called "down". A model that always says "up" gets 100% and 0%, so its BA is exactly 0.5.

翻成中文：平衡準確率（Balanced accuracy，BA）是兩個命中率（這裡指在某一類日子裡猜對的比例）的平均：

- 一個是漲的日子裡，被判為「漲」的比例。
- 另一個是跌的日子裡，被判為「跌」的比例。

一個永遠說「漲」的模型，這兩個比例分別是 100% 和 0%，所以它的 BA 剛好是 0.5。

### 4.1 用 10 天算一次

假設有 10 天，其中 6 天漲、4 天跌。比較兩個模型：

| | 漲的 6 天裡猜「漲」 | 跌的 4 天裡猜「跌」 | 總共猜對 |
|---|---|---|---|
| 模型 X（永遠說漲） | 6 天 | 0 天 | 6 天 |
| 模型 Y | 3 天 | 3 天 | 6 天 |

**準確率（accuracy）= 猜對天數 / 總天數**

- X：6/10 = 0.6
- Y：6/10 = 0.6

兩個模型的準確率一樣，看不出差別。

**BA = 兩個命中率的平均**

- X：漲日命中率 6/6 = 1，跌日命中率 0/4 = 0。BA = (1 + 0) / 2 = **0.5**。
- Y：漲日命中率 3/6 = 0.5，跌日命中率 3/4 = 0.75。BA = (0.5 + 0.75) / 2 = **0.625**。

X 只是一直說同一個答案，完全沒分辨漲跌。Y 在漲日和跌日都猜對了一部分，真的有在分辨。BA 分得出這兩者，準確率分不出來。

### 4.2 為什麼會這樣：權重不同

準確率也可以寫成兩個命中率的加權平均。權重是各類日子佔的比例：

```
accuracy = 0.6 × 漲日命中率 + 0.4 × 跌日命中率
```

- 模型 X：0.6 × 1 + 0.4 × 0 = 0.6
- 模型 Y：0.6 × 0.5 + 0.4 × 0.75 = 0.3 + 0.3 = 0.6

漲的日子比較多，所以準確率比較在意漲日猜得對不對。永遠說漲，就能拿下那 60%。

BA 則固定給兩類各 0.5 的權重，不管哪一類天數多：

```
BA = 0.5 × 漲日命中率 + 0.5 × 跌日命中率
```

所以只顧一邊、放棄另一邊，BA 最多就是 0.5。

### 4.3 「剛好 0.5」對所有只回答同一個答案的模型都成立

- 永遠說「漲」：(100% + 0%) / 2 = 0.5
- 永遠說「跌」：(0% + 100%) / 2 = 0.5

這兩個結果跟漲跌各佔幾天無關。不管是 6 漲 4 跌還是 9 漲 1 跌，算出來都是 0.5。所以 BA = 0.5 就是「沒有分辨能力」的基準線。

### 4.4 和第 3 節的名詞對照

- 漲日命中率 = TP / (TP + FN)，就是 TPR，也叫 Recall。
- 跌日命中率 = TN / (TN + FP)，叫 TNR（True Negative Rate）或 specificity，等於 1 − FPR。

所以 BA = (TPR + TNR) / 2。

BA 和 AUC 的差別：BA 要先選一個門檻、把分數變成「漲／跌」再算，看的是這一個門檻下的表現；AUC 把所有門檻都試過，看的是整體排序。

### 4.5 放回專題的數字（h=5，2019–2025）

- 這段期間 61.4% 的日子是漲。chance 基準每天都說漲，所以準確率是 0.614，但 BA 是 0.500。
- TimesFM 的 BA 是 0.467，低於 0.5。意思是它在漲日和跌日的命中率平均起來不到一半，比「永遠說漲」這種沒有資訊的做法還差。
- fixed LR 的 BA 是 0.536，是三者中唯一高於 0.5 的。
